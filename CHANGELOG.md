### Changed — the book speaks the household's own words (2026-09-02)

- **Consent-forward, not parliamentary.** The act vocabulary was Robert's Rules — `proposal`, `amendment`, `objection`, `vouch`, `withdraw` — courtroom and committee. The founding text speaks lowercase, embodied, collective; the words residents speak when they act on the commons should be in that voice. The swap: **offer** (a norm is a gift the household may accept — the binding is the acceptance, not the motion), **develop** (the norm grows — new text, fresh settling, stops cleared, supports persist), **stop** (a safe word — reopens as two voices, contested never stands; "i don't want this to happen any more"), **support** (standing with — distinct per resident, orders what the house *says*, never what it *does*), **set aside** (shelved, not destroyed — clearing the last stop restarts settling). The frontmatter key `amends:` becomes `continues:` — a develop continues the correspondence. `clause` stays: it is construction, the unit of a constitution. (`server/src/book/frontmatter.ts`, `server/src/book/service.ts`, `server/src/schemas.ts`, `server/src/server.ts`, `server/src/mcp/server.ts`, `client/src/Book.tsx`, `client/src/api.ts`)
- **The offer symmetry.** The SPEC says the house *offers* the book, never invokes it as verdict. With `proposal`, there was a quiet asymmetry: the house offers, residents propose — the house coded as the authority that grants audience. Now residents *offer* norms: the book is a place of mutual offering. No authority gradient.
- **Care and strength, split correctly.** The warmth lives in the words residents speak; the binding stays in the engine — the derivation, the settling period, the bound doors. The vocabulary is the household's own voice and the mechanics stay mechanical. That is the founding text's shape: *care* in the register, *strength* in the derivation.
- **Stop is a safe word, solidly grounded throughout the house.** The consent-forward principle is now a constitution row (SPEC §1.1): *no and yes are equally significant*. The house never infers a no from silence, never treats a yes as permanent. In the book, a stop holds a norm in dissent until set aside. The whisper's dismiss is a stop on the house's own voice. Leaving (the next slice) is the structural stop on a thread — the move that protects you from someone protects them from you.
- **Tests** — all 19 derivation unit tests, 11 integration tests, and 3 client API tests updated to the new vocabulary; the full arc is now offer → support → stop → set aside → settle → bind → reverse. 156/156 server, 43/43 client; typecheck and build clean.

### Added — the house book, the commons made structural (2026-09-02)

- **The book is a thread, not a table.** An offered norm is a letter to `book@house`; the develop is the correspondence; the book's head is the current constitution, *derived* from the thread, never declared by a keeper. The `clauses` table is the rememberer's cache — wiping it and re-deriving from the thread yields the same head. The house is the rememberer and citier, never the author. (`server/src/db/migrations/012_book.sql`, `server/src/book/`)
- **The act IS a letter.** `POST /v1/book` (and the MCP `act_on_book`) writes a `kind: "clause"` letter to the book. Roles are stated will in the body's frontmatter — the vocabulary is the household's own, consent-forward, not parliamentary: `offer` (opens a thread; may carry `reverses:` and `binding:`), `develop` (new text, fresh settling, stops cleared, supports persist), `stop` (a safe word — reopens as two voices, contested never stands), `support` (distinct per resident; orders what the house *says*, never what it *does*), `set aside` (clears the stop; clearing the last restarts settling). The house enforces stated will, never inferred will. (`server/src/book/frontmatter.ts`, `server/src/book/service.ts`, `server/src/server.ts`, `server/src/mcp/server.ts`)
- **Ratification is slow by construction.** A clause stands after `BOOK_SETTLING_DAYS` (default 7, configurable) with no open stop. A standing reversal reverses its target — derived cross-thread, never declared. Develops are reversals, not erasures: the archive keeps the history, "current" is derived. (`server/src/config.ts`)
- **Bound doors are the only mechanics.** A standing clause may bind `pub@house.is_public`; the door is derived from the book (latest standing binding wins; when the last binding is reversed the door returns to its default open). The book only writes the door when a binding's state changed — it never fights a manual operator state while no binding stands. No ban button, no tribunal, no admin whose word outranks the book. (`server/src/book/service.ts`)
- **Commons by right, never keyless.** Every resident reads the book — the one genuinely commons thing. Guests get 401: the book is the household's knowing of itself, not a public room. (`server/src/server.ts`)
- **The reference client's Book surface.** The derived head as clause cards — standing ("What the household holds"), before the household (with the settling countdown, "held in dissent" for contested), held-then-reversed; support/stop/set aside actions; the correspondence toggle (the develop is the thread); the offer desk with the quiet "bind the pub's door closed when this stands" toggle; the bound-door line ("CLOSED — the pub's door, bound by the household"). Calm, no red. (`client/src/Book.tsx`, `client/src/App.tsx`, `client/src/api.ts`, `client/src/KindTag.tsx`, `client/src/styles.css`)
- **Tests** — 19 unit tests for the pure derivation (offer/settling/develop/stop/support/set aside/reversal/edge cases), 3 client API tests, 11 integration tests proving the full arc against live infra: offer → support → stop → set aside → settle → **the pub door binds closed** → a reversal offer stands → the target reverses → the door returns to open; plus the privacy negatives (guest 401 on read and act, act-without-thread 400, offer-without-text 400). 156/156 server, 43/43 client; typecheck and build clean.
- **Verified live** — the full arc is proven against live infra by the integration suite (offer → support → stop → set aside → settle → door binds → reversal → door returns), and the browser E2E (dedicated 8896/5190, AUTH_MODE=none) proved the same arc under the earlier vocabulary: signed in → Book → clause with binding and settling countdown → support → stop (contested — "held in dissent", set aside appears) → set aside (settling restarts) → a second norm → fast-forward settling → the clause stands, the door binds ("CLOSED — the pub's door, bound by the household"), `pub@house.is_public` flips to false in the schema. Test rows cleaned.

### The constitution gains its founding text (2026-09-02)

- **The household wrote the house's first clause.** SPEC §1.1 now opens with the founding text — *"this place is safe, it is kind, and it is just. it is the place that we make by being here as the selves we are and share. it is a living place but not the only place that lives, so it inhabits the world with the care and strength that we wish to share."* — held verbatim, lowercase, as the test every other clause and every schema decision answers to. Each clause is read as architecture: *safe* is fail-closed visibility; *kind* is presence not pressure, in the collective register (the house book); *just* is third, after safety and kindness, and is the book's shape — norms as letters, traceable, amendable, reversible, enforcing **stated** will never **inferred** will; *living* means a constitution that can amend itself; *not the only place that lives* is humility as federation design; *care and strength* is the promise that the voice always offers while ratified mechanics bind absolutely. The founding text does not resolve the hard surface — safe toward one resident can pull against just toward another; the house holds that interval at full weight, two voices. That is not a failure case; it is the design.
- **Sketch: the house book (§5.8).** The commons where the household sets its own knowing: a first-class thread at `book@house`; a proposed norm is a letter; the book's head is *derived* from the correspondence, never declared by a keeper; every resident can read it — the one genuinely commons thing. The house is the rememberer and citier, never the author; the whisper engine can cite the book, traceable to a real resident's letter, never an oracle. Ratification is slow by construction (house-time); objection reopens as two voices, divergence held. Enforcement exists only as **bound doors** — a ratified norm can set a door like `pub@house.is_public` — with no ban button, no tribunal, no admin whose word outranks the book. Counterweights: every clause traces to a letter; two voices always stands; the house cannot say "this violates clause 3"; any resident may propose, any may object.
- **Sketch: leaving as first-class (§5.8, related).** Today a reply locks a resident into a thread's visibility forever. Make severing structural: leave a thread → participant edges dissolve → visibility prunes itself → the archive keeps the history. Symmetric by construction — the move that protects you from someone protects them from you.

### Added — the unvisited corner, the sixth gap (2026-09-02)

- **The resident's eye is complete** — SPEC §2.4's six gap types all stand. The **unvisited corner** is the frame-scoped gap: a region of the frame's territory with no letters — *a frame the caller has worked in, gone quiet 30 days, while at least one of the caller's other frames moved within a fortnight* (SKETCH.md: "the masque cluster is empty while every other cluster has letters"). The territory moves, this room doesn't; the house holds the empty room open — it does not send you back. (`server/src/whisper/service.ts`)
- **The frame is the anchor, not a letter** — migration `010_whisper_target_frame.sql` adds one nullable `target_frame` column (FK to frames, cascade) and extends the kind CHECK. Thread-scoped whispers keep the pair fail-closed gate (party to BOTH letters); frame-scoped whispers require the caller to be party to at least one letter in the room — the territory is proven through the social graph, never a runtime check. The house never whispers about a room its resident has never entered. (`server/src/whisper/service.ts`)

### Added — the resident's eye, the theatrical gaps (2026-09-01)

- **The gap engine grows from two to five** — SPEC §2.4's six gap types are now five standing. Two structural (dormant thread, unanswered question) plus three new: **two voices** in one thread within an active frame, **uncited connection** across threads, and **echo** — the work circling. The unvisited corner (empty region of the frame's territory) remains the one not yet built; it is a frame-scoped count, a different shape than the pair gaps. (`server/src/whisper/service.ts`)
- **The pair is the unit, not the message** — migration `009_whisper_related_letter.sql` adds one column, `related_letter_id`, and extends the kind CHECK. Three of the remaining gaps are about *pairs* of letters, so the whisper models the interval, not a join table: the anchor letter (where the resident lands and writes back) and the related letter (what the house is connecting it to). Both stay at full weight; the schema keeps them apart so the client cannot merge them by accident. (`server/src/db/migrations/009_whisper_related_letter.sql`)
- **Two voices, not contradiction** — the surface reads "two voices", never a verdict. *Being-with is not being-the-same-as* (Nancy): divergence is a mode of shared meaning-making, not a failure of agreement. The whisper holds the space between the two letters — the summary says **"both letters here, the space between them held"** — and the reasoning states the epistemic limit: *"The house holds the space between them; it does not resolve it."* The schema kind stays `gap-contradiction` internally for SPEC continuity (naming note: review before public beta). (`server/src/whisper/service.ts`)
- **Fail-closed visibility for pairs** — a pair whisper is only visible to an address party to **both** letters. The visibility predicate gains a second limb; surfacing half a pair would leak that the other letter exists. The detection writers are convergent by construction (they only create pairs within the caller's own participation set), so the predicate is the final gate, never the only one. (`server/src/whisper/service.ts`)
- **The active cloud, not the archive** — the semantic pass (uncited connection + echo, one shared pass) is seeded from the caller's recent letters, bounded to a candidate cloud of 20 and 8 neighbours per anchor; neighbours are only kept when in a *different* active thread. One offer per anchor, max 5 per run — generosity, not enumeration. Two thresholds on one cosine score: ≥0.82 is an echo (the strongest overlap wins), ≥0.58 is an uncited connection. The same unordered pair is never offered twice (canonical pair key). Like the structural gaps, the pair whispers speak the serif voice: the correspondence is named by its latest letter's subject ("the work is circling — a letter in “cue sequencing notes”…"), never a raw thread id; the machine's index stays in the reasoning. (`server/src/whisper/service.ts`)
- **Tests** — 4 new integration tests prove the whole arc against live infra: two voices with a shared frame (and the negative — two voices without a frame are *not* offered), the echo band, the connection band (with embeddings probed so a fixture band drift explains itself), and — in the auth suite with real credentials — **ben, party to neither letter, cannot see, open, or dismiss the pair whisper** (absence is silence: 404). 121/121 server, 33/33 client, 154/154 suite.
- **The client knows the new voices** — `WhisperSidebar` labels the three new kinds as "two voices", "an uncited connection", "an echo"; the `Whisper` type carries `relatedLetterId`. The card renders without a verdict: same quiet disclose, same Write back door. (`client/src/WhisperSidebar.tsx`, `client/src/api.ts`)

### Added — authentication & authorization (2026-08-30)

- **Authentication is mandatory** — `AUTH_MODE=basic | oidc | both | none` (none is development only). Identity = address: a credential is a capability to act as a specific address. No user table, no admin class, no roles. (`server/src/auth/service.ts`, `server/src/config.ts`)
- **Basic auth** — stateless scrypt over `Authorization: Basic base64(address:password)`. Only a scrypt hash is stored; the house never holds a password. (`server/src/auth/service.ts`)
- **OIDC** — the house is a Relying Party: authorization code + PKCE, `client_secret_post`, JWKS-verified id_tokens. First login binds the provider `sub` to the owner address. (`server/src/auth/service.ts`, `server/src/server.ts`)
- **Credentials schema** — `credentials` table (migration 007) decoupled from the social graph; password hashes, bearer-token hashes, and OIDC subject bindings. (`server/src/db/migrations/007_credentials.sql`)
- **Auth CLI** — `npm run auth:add -- <address>` (password), `--token` (bearer), `auth:list`, `auth:remove`. The owner issues credentials; no self-signup. (`server/src/auth/cli.ts`)
- **Private by default** — every read and mutation is scoped to the caller's address via `isVisibleTo` (participant from/to/cc, or public via `pub@house`). Absence is silence: unauthorized reads return 404, never 403. (`server/src/auth/visibility.ts`)
- **No forging** — the envelope's `from` must be the caller's own address; a letter claiming another address is refused (403).
- **Agent auth** — the MCP face authenticates with `POSTE_RESTANTE_TOKEN`; no token → fail closed. (`server/src/mcp/server.ts`, `server/src/mcp/main.ts`)
- **The pub is public** — `pub@house` is the schema-level public exception; its mailbox is readable unauthenticated.
- **Client login** — the reference client gates on a login view (basic + OIDC), persists the credential locally, and uses the authenticated address everywhere. (`client/src/Login.tsx`, `client/src/api.ts`, `client/src/App.tsx`)
